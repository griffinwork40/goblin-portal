# T2.4 Scrollback Measurements — 2026-10-09

## Context

T2.4 from the best-mac-terminal roadmap: size the default scrollback for agent REPL
transcripts (previously 1000 lines), after measuring cost and fixing the 1% scrollbar thumb
floor. Agent sessions routinely exceed 1000 lines.

**Summary of outcome**: default raised from 1000 to **5000** lines (Config.swift:284,
AppConfig.defaults()). The prior decision to keep 1000 was based on DEBUG SwiftTerm
measurements (~25× slower than the shipped release binary). Re-measured with RELEASE
SwiftTerm: 5k p50 ≈ 5,098 µs (~5.1 ms) = 31% of a 16.7 ms frame — the correct tradeoff for the
default. Details below.

---

## 1. Root cause: 1% scrollbar thumb floor

`AppleTerminalView.swift:2057` (vendor, before patch 0015):
```swift
return max (CGFloat (displayBuffer.rows) / CGFloat (displayBuffer.lines.count), 0.01)
```

`lines.count = scrollback + rows`. With 46-row terminal:
- 1000 scrollback → `46/1046 ≈ 0.044` (4.4%) — proportional
- 3500 scrollback → `46/3546 ≈ 0.013` (1.3%) — barely proportional
- 4554 scrollback → `46/4600 = 0.010` → 1% floor kicks in
- 5000 scrollback → `46/5046 ≈ 0.0091` → **floored at 1%** always
- 10000 scrollback → `46/10046 ≈ 0.0046` → **floored at 1%** always

At 5000+ lines, the thumb is ALWAYS 1% regardless of how much of the scrollback is filled.

**Fixed by vendor patch 0015**: replaces `0.01` with `1.0 / CGFloat(displayBuffer.rows)`.
At rows=46: min = `1/46 ≈ 0.022` (2.2%). Proportional and honest at any depth.
NSScroller handles any knob proportion correctly.

## 2. Memory measurements (phys_footprint delta, RELEASE SwiftTerm, 2026-10-09)

Method: `task_info(TASK_VM_INFO).phys_footprint` delta — process RSS before/after
creating a HeadlessTerminal with the given scrollback and filling it. Each measurement
runs in a fresh process invocation to avoid accumulation. Machine: M4 Pro.

**CharData stride: 24 bytes** (measured from live binary).
MemoryLayout<CharData>.stride × cols × (scrollback + rows) = LOWER BOUND only;
actual phys_footprint includes BufferLine object overhead.

### 80 columns

| Scrollback | Stride lower bound | phys_footprint delta | Per 1k lines |
|------------|-------------------|---------------------|--------------|
| 1,000 | 1,961 KB | 2,576 KB | 2.5 MB/1k |
| 5,000 | 9,461 KB | 8,528 KB | 1.7 MB/1k |
| 10,000 | 18,836 KB | 10,640 KB | 1.0 MB/1k |

### 200 columns

| Scrollback | Stride lower bound | phys_footprint delta | Per 1k lines |
|------------|-------------------|---------------------|--------------|
| 1,000 | 4,903 KB | 5,408 KB | 5.3 MB/1k |
| 5,000 | 23,653 KB | 20,640 KB | 4.0 MB/1k |
| 10,000 | 47,090 KB | 25,712 KB | 2.5 MB/1k |

Gate ceiling: 8 MB/1k lines phys_footprint. All measured values pass.

**5k pane budget**: 80 cols → 8.5 MB; 200 cols → 21 MB. Well within budget (a terminal
pane also carries a Metal atlas ~5-10 MB and CA backing ~5-10 MB).

## 3. Resize cost measurements

### 3a. DEBUG SwiftTerm (SUPERSEDED — kept for reference)

Measured 2026-10-09, debug build, M4 Pro, load ≈ 0.2/CPU.
Method: `Terminal.resize(cols: 40, rows: 46)` + `resize(cols: 80, rows: 46)`, 50 iters.

| Scrollback | p50 (µs) | p95 (µs) | % of 16.7ms frame |
|------------|----------|----------|-------------------|
| 1,000 | 12,900 | 13,100 | **77%** |
| 3,500 | 43,200 | 44,100 | **258%** |
| 5,000 | 61,300 | 62,100 | **367%** |
| 10,000 | 122,300 | 123,300 | **732%** |
| 20,000 | 242,500 | 246,500 | **1452%** |

**These numbers are WRONG for the shipped app.** The shipped app is a RELEASE build.
Debug SwiftTerm is ~25× slower due to unoptimised Buffer.resize reflow. The original
T2.4 decision to keep 1000 was made from these numbers. That decision was incorrect.

### 3b. RELEASE SwiftTerm (AUTHORITATIVE, 2026-10-09)

Measured with `swift build -c release --build-system swiftbuild`, harness compiled -O.
Machine: M4 Pro, load 0.38-0.59/CPU during timing runs.

| Scrollback | p50 (µs) | p95 (µs) | 3×p95 ceiling | % of 16.7ms frame |
|------------|----------|----------|---------------|-------------------|
| 1,000 | 483 | 561 | 1,683 | **2.9%** |
| 3,500 | 2,656 | 3,593 | 10,779 | **15.9%** |
| 5,000 | 5,098 | 5,888 | 17,664 | **30.5%** |
| 10,000 | 10,852 | 11,990 | 35,970 | **65.0%** |
| 20,000 | 22,052 | 22,799 | 68,397 | **132%** |

Gate ceilings = 3× release p95 (see check-scrollback-cost-harness.swift for rationale).
Debug falsification: 1k debug p50 = 12,349 µs >> 1,683 µs ceiling → exit 1 (confirmed).

---

## 4. Decision: RAISE default to 5,000 lines

Evidence:
- **Release resize at 5k: 5,098 µs (~5.1 ms) p50 = 31% of frame** — leaves 69% for rendering during
  live drags. Perceptible only during sustained 60 fps drag at a maximally-stressed buffer.
  This is the same per-frame overhead ratio as many production terminals.
- **Release resize at 10k: 10.9 ms p50 = 65% of frame** — leaves only 35%. Drag stutter
  is likely. 10k is NOT the right default.
- **Memory at 5k, 80 cols: 8.5 MB phys_footprint** — well within budget.
- **Scrollbar thumb fixed by patch 0015**: thumb is now proportional at any depth.
- The prior 1000-line default was based on debug measurements that were 25× too pessimistic.

**Final default: 5,000 lines** (Config.swift:284, PreferencesDiff.defaultScrollback).

To raise further (>5k): re-run `check-scrollback-cost.sh` and verify release p50 stays
below 8 ms (~48% of frame budget) before editing `AppConfig.defaults()`.
