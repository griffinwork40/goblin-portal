feat(app): T2.5 — deferred notification permission at first relevant use

Move the UNUserNotificationCenter permission prompt from applicationDidFinish
Launching to the first notification that would actually be posted.

Changes
-------
NotificationPermissionPolicy.swift (new, 137 LOC)
  Foundation-only state machine: AuthState x notificationRequested -> NotificationAction.
  States: notDetermined -> pending -> authorized/denied. Actions: requestThenPost,
  post, enqueue, drop. Burst queue capped at maxQueued = 5. authorizationCompleted
  flushes or discards the queue. applyKnownState skips when not in notDetermined.

CommandNotification.swift (132 -> 186 LOC)
  Removed requestPermissionIfNeeded(). All delivery now routes through post()
  which consults policy.notificationRequested and acts on the returned action.
  The .requestThenPost case carries the first event's payload into the completion
  handler so it is posted AFTER the grant -- macOS silently drops a notification
  added before authorization, so this is load-bearing, not an optimisation.
  DispatchQueue.main.async hops back to the @MainActor-guarded policy after the
  system callback (which arrives on an arbitrary thread).

AppDelegate.swift (345 -> 340 LOC)
  Removed the requestPermissionIfNeeded() call and its 5-line comment block.
  The UNUserNotificationCenter.current().delegate = self line is unchanged
  (required so the app receives banners while frontmost).

check-command-notification.sh
  Added NotificationPermissionPolicy.swift to the compile step.

check-notification-permission.sh (new, 270 LOC)
  Part A: three structural wiring greps.
  Part B: 29-case compiled truth table over NotificationPermissionPolicy.
  Part C: three falsification mutants.
